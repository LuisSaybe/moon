# Moon API

TypeScript GraphQL API using `@apollo/server` with its Express 5 integration.
Vite compiles the server. Apollo handles requests at `/graphql`, with JSON body
parsing, CORS, and Prisma available in the request context. The sample collection
is stored in memory.

The setup follows the [Apollo Express integration](https://www.apollographql.com/docs/apollo-server/api/express-middleware).
Production shutdown drains HTTP requests, stops Apollo, and disconnects Prisma.

## Docker

From this directory, run:

```sh
docker compose up --build
```

The existing Compose setup installs dependencies with `npm ci`, then starts
Vite at http://localhost:5173/graphql. Source changes take effect on the next
request.

If the web app already occupies port 5173, use a different host port:

```sh
docker compose run --rm --build -p 5174:5173 vite
```

In that case, use port 5174 in the example below.

## Query

```sh
curl http://localhost:5173/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ items { id name } }"}'
```

```json
{"data":{"items":[{"id":"1","name":"Moon"},{"id":"2","name":"Mars"},{"id":"3","name":"Venus"}]}}
```

## Local development and production build

With Node.js 24:

```sh
npm ci
npm run dev
```

`npm run lint` checks JavaScript and TypeScript files with ESLint's recommended
rules and Node.js globals. Generated `dist` files are ignored.

ESLint's TypeScript parser currently requires TypeScript 6. The
`typescript-compiler` alias retains TypeScript 7 for `npm run check` and builds;
the separate `typescript` dependency supports linting.

`npm run check` checks types. `npm run build` checks types and uses Vite to
compile `src/server.ts` into `dist/server.js`. `npm start` serves that build
with Node.js; set `PORT` to change its default port of 5173.

To build using the existing Docker image:

```sh
docker compose run --rm install
docker compose run --rm --no-deps vite npm run build
docker compose run --rm --no-deps -p 5174:5173 vite npm start
```

## PostgreSQL and Prisma

Compose starts PostgreSQL 17 with a persistent `postgres_data` volume, applies
committed Prisma migrations, and then starts the API. Local development credentials
are `moon` / `moon`, with database `moon` on `localhost:5432`.

For development outside Docker, first start the database:

```sh
docker compose up -d postgres
cp .env.example .env
npm ci
npm run db:deploy
npm run dev
```

The Prisma model `GameObjectDefinition` has only an `id` primary key, stored as a
PostgreSQL UUID and generated by PostgreSQL. Import `prisma` from `src/db.ts` to
query it, for example `await prisma.gameObjectDefinition.create({ data: {} })`.
The API connects through Prisma when its application module loads.

`npm ci` generates the Prisma client. After schema changes, run
`npm run db:migrate -- --name describe_change` and `npm run db:generate`.
Set `DATABASE_URL` for another database; Compose supplies its internal hostname
`postgres`, while `.env.example` uses `localhost`. The migration and connection
setup follow the [Prisma PostgreSQL documentation](https://www.prisma.io/docs/orm/v7/core-concepts/supported-databases/postgresql).
